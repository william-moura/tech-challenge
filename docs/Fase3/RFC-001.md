# 📜 RFC 001: Arquitetura de Autenticação Serverless com CPF e JWT

* **Status:** Aprovado
* **Data:** 15 de Setembro de 2026
* **Autores:** Grupo SOAT - Software Architecture

---

## 1. Contexto e Problema
A oficina mecânica precisa proteger rotas sensíveis do sistema (como abertura e alteração de Ordens de Serviço). É necessário controlar acessos e autenticações com segurança, validando a identidade do cliente pelo CPF antes de liberar o consumo das APIs protegidas.

---

## 2. Proposta de Solução
Implementação de uma função Serverless (**AWS Lambda**) exposta por um **AWS API Gateway v2 (HTTP API)**.

### Fluxo de Funcionamento:
1. O cliente consome o endpoint `POST /auth` enviando seu CPF.
2. A Lambda valida o formato do CPF e consulta a existência/status do cliente na base de dados.
3. Se válido, a Lambda gera e devolve um token JWT (JSON Web Token) com assinatura e tempo de expiração definidos.
4. O cliente inclui o token no cabeçalho `Authorization: Bearer <token>` para consumir as APIs protegidas do cluster Kubernetes.

---

## 3. Alternativas Descartadas
* **Autenticação Embutida no Monolito:** Descartada para desonerar o cluster K3s do processamento de requisições de autenticação maliciosas ou malformadas.
* **AWS Cognito:** Descartado devido às restrições de customização e regras de validação de CPF no ambiente AWS Academy.
