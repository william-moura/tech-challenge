# 📜 RFC 002: Estratégia de Segregação de Repositórios e CI/CD

* **Status:** Aprovado
* **Data:** 15 de Setembro de 2026
* **Autores:** Grupo SOAT - Software Architecture

---

## 1. Contexto e Problema
Para garantir responsabilidade única, governança de código e entregas contínuas independentes, a arquitetura da aplicação precisa ser dividida em múltiplos repositórios com automação de deploy na nuvem.

---

## 2. Proposta de Solução
Organização do projeto em **4 repositórios distintos**, cada um com sua própria pipeline de CI/CD via GitHub Actions e regras de proteção de branch:

1. **`tc-soat-auth-lambda`:** Código-fonte e pipeline de deploy da Function Serverless.
2. **`tc-soat-k8s-infra`:** Código Terraform para provisionamento de EC2, Security Groups, API Gateway v2 e manifestos do K3s.
3. **`tc-soat-db-infra`:** Código Terraform para provisionamento do AWS RDS MySQL 8.0.
4. **`tech-challenge`:** Código da aplicação principal Laravel, Dockerfile e automação de rollout/migrations via SSH.

---

## 3. Regras de Proteção de Código
* A branch `main` é protegida contra commits diretos.
* Alterações exigem Pull Request (PR) aprovado antes do merge.
* Merge na branch principal dispara automaticamente a pipeline de deploy para a nuvem.
